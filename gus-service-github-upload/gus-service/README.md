# ГУСЬ.СЕРВИС

Полноценный Next.js-проект с Supabase Auth, PostgreSQL, входом по email **или логину**, историей заказов и каталогом тарифов/сертификатов.

## Что уже работает после настройки Supabase

- Регистрация по email, логину и паролю.
- Вход по email **или** логину и паролю. Для входа по логину сервер находит email в профиле и не возвращает его клиенту.
- Выход и серверные cookie-сессии через `@supabase/ssr`.
- Подтверждение email, если оно включено в настройках Supabase.
- Профиль и история заказов, защищённые RLS.
- Каталог из 6 тарифов, дополнительные опции, расчёт суммы и промокоды `GUS10`/`GUS500`.
- Подарочный сертификат на 10 000 ₸ с кодом `GUS-G50XHM`.
- Подготовленный блок поддержки для будущего Telegram-бота.

## Важно перед публикацией

Оформление заказа **сохраняет заявку**, но не принимает оплату и не отправляет её автоматически в Telegram. Это не платёжный сервис. Тарифы и промокоды в коде являются серверными стартовыми значениями, их нужно менять в `app/api/orders/route.ts`.

## 1. Создай проект Supabase

1. Открой https://supabase.com/ и создай новый проект.
2. В проекте открой **SQL Editor → New query**.
3. Скопируй весь файл `supabase/schema.sql`, выполни его и проверь, что запрос завершился без ошибок.
4. Открой **Project Settings → API** (или раздел API Keys в актуальном интерфейсе).
5. Скопируй Project URL и publishable/anon key. Также найди `service_role` secret key. Названия вкладок могут меняться в интерфейсе Supabase.
6. В **Authentication → URL Configuration** укажи локальный адрес `http://localhost:3000` как Site URL. Перед публикацией добавь настоящий домен в Site URL/Redirect URLs.
7. Для регистрации по email оставь подтверждение включённым, если хочешь требовать подтверждение адреса. Настрой SMTP, если письма не доставляются.

## 2. Настрой переменные окружения

Скопируй `.env.example` в `.env.local` и заполни значения:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_SECRET
```

**Никогда не публикуй `SUPABASE_SERVICE_ROLE_KEY`, не добавляй к нему префикс `NEXT_PUBLIC_` и не отправляй его в клиентский код.** Не коммить `.env.local` в Git. Если секрет случайно попал в репозиторий, немедленно ротируй его в Supabase.

## 3. Запусти локально

Нужен Node.js 20.9+.

```bash
npm install
npm run dev
```

Открой http://localhost:3000. Для проверки создай аккаунт, подтверди email (если требуется), войди по email и выйди. Затем проверь вход по логину и оформление заказа.

Проверка production-сборки:

```bash
npm run build
npm start
```

## 4. Публикация на Vercel

1. Создай приватный репозиторий GitHub и загрузи файлы проекта **без** `.env.local`.
2. Импортируй репозиторий на https://vercel.com/.
3. В Vercel Project Settings → Environment Variables добавь все три переменные из `.env.local`. `SUPABASE_SERVICE_ROLE_KEY` должен быть server-only.
4. Deploy.
5. Скопируй домен Vercel и добавь его в Supabase Authentication → URL Configuration: Site URL и Redirect URLs.
6. Проверь регистрацию, подтверждение email, вход по email/логину и создание заказа на опубликованном домене.

## 5. Как работает логин по имени

Supabase Auth принимает email и пароль, а не произвольный username. Поэтому `/api/auth/login` при получении логина делает серверный запрос к `profiles` с помощью service-role клиента, получает email внутри сервера и передаёт пару email/пароль в обычный Supabase Auth. Email не возвращается браузеру. Клиент не может читать чужие профили из-за RLS.

## 6. Telegram-бот позже

В `app/components/Storefront.tsx` есть блок «Поддержка скоро прилетит». Когда будет готов бот, добавь серверный endpoint, который безопасно отправляет уведомление о новом заказе в Telegram. Токен бота должен быть только в серверной переменной `TELEGRAM_BOT_TOKEN`, а `chat_id` администратора — в `TELEGRAM_ADMIN_CHAT_ID`. Не храни токен в React/клиентском коде. Для реальных заказов также добавь проверку статуса, rate limiting и антиспам.

## Архитектура

- `app/page.tsx` — серверная страница и загрузка аккаунта/заказов.
- `app/components/Storefront.tsx` — интерфейс магазина и формы.
- `app/api/auth/*` — регистрация, вход, выход.
- `app/api/orders/route.ts` — серверная проверка сессии и создание заявки.
- `lib/supabase-server.ts` — клиент Supabase с cookie-сессией.
- `lib/supabase-admin.ts` — server-only клиент для поиска email по логину.
- `supabase/schema.sql` — таблицы, триггеры и политики безопасности RLS.

## Ограничения стартовой версии

- Нет онлайн-оплаты, отправки SMS, CAPTCHA или ограничения частоты запросов. Перед широкой публичной рекламой стоит добавить rate limiting/CAPTCHA на auth endpoints.
- Статус заказов сейчас можно менять только через доверенный административный доступ в Supabase. Клиент не имеет права редактировать итоговую сумму или статус.
- `GUS-G50XHM` отображается как сертификат-витрина. В этой версии нет проверки остатка сертификата, одноразового погашения или автоматической выдачи уникальных сертификатов.
- Промокоды демонстрационные и не ограничены по числу применений.
